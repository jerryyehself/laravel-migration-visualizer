## 核准範圍與操作規則

1. **同一步驟**：選 migration 後，圖、逐檔摘要與診斷同步到該檔。工作區固定顯示原始順序位置、檔名與狀態。全域專案診斷仍保留並明確標示範圍。
2. **順序閱讀**：用前一份／下一份與套用前／後／比較操作，不再把檔案與側別混成主要的 3N+2 長選單。按原始 core 順序移動，不自動跳過 failed／blocked；端點禁用並清楚標示。搜尋／篩選沿用已有能力，不改 core 順序。
3. **選表明細**：單擊表可選取並顯示明細，拖移仍調整位置；提供鍵盤等效操作、選取與焦點回饋。明細有固定區域，未選表時顯示提示；搜尋或圖選取應產生一致結果。
4. **持續查看**：換 migration／側別時保留明確選中的表名稱。該側沒有該表就顯示不存在，快照未知就顯示未知；不默默換表、不複製另一側資料、不自動追改名。表名稱是 literal query，不是穩定物件身分。
5. **來源預覽與返回**：在明細區提供現有 PHP 原始碼／行號與操作狀態的唯讀預覽，預覽不改目前閱讀步驟。關閉／返回後仍是進入前的表、步驟與側別，保留可恢復的 view／焦點；不得為看另一份來源而暗中換圖。
6. **可信提示**：失敗與 blocked 的 operations 仍是語法證據，不能顯示為已套用；final 未知、已知空 schema、表不存在各自顯示。來源找不到或不唯一則說明，不猜檔名。

同工作區保留既有初始／最終結構入口，不能刪掉為方案 A；不另新增 B 的分頁架構。分析後的預設最終結構仍依 complete 判定，未知不以 lastValid 補值；選 migration 才進入該步驟檢視，首次可預設套用後，明確顯示所選側別。

篩選列表不應暗中改變閱讀時點；若目前步驟不在篩選結果，顯示提示。前一份／下一份仍依完整原始順序，工作區顯示原始位置，避免錯把篩選後第幾項當作分析順序。

不要求全部快照使用同一份永久布局。既有比較的兩圖同步互動保留；快照切換仍可重設 view，但不能因此失去正在查看的表名稱。修改輸入後沿用舊結果失效、重新分析及副本修正／還原規則。

## service／DTO 邊界與預計檔案

像後端 service 已回傳每份 migration 的 before／after／diff DTO，畫面只整理「目前讀哪份 DTO、哪一側、哪張表」。不新增 Laravel service，不解析 Eloquent model，不在 React 中 parse／replay，也不改 core 或公開 JSON。

## 具體驗收任務

1. 既有 project 三檔：選 users，在第二份看到 nickname 新增；按下一份在第三份看到移除，查看 PHP 來源後回到第三份 users，不需重新搜尋表。比較模式移除欄位只存在 before。
2. 第二份明確 rename name→display_name，第三份 drop 後同名重建：操作與結構 diff 如實呈現，不假稱 changeColumn 或自動串接欄位身分。
3. 選一份 migration、換前／後／比較，圖、摘要、診斷與明細的檔名／時點一致。另一檔來源預覽不能改目前圖的時點。
4. 既有 table-lifecycle 刪表情境：保持查看同名字串，在表不存在的側別顯示不存在；不存在不等於快照未知。
5. R6 固定真實樣本：Laravel.io 仍因 after(callback) 不完整、BookStack 仍因 DB write 不完整；只檢查本批 UI 能清楚閱讀狀態，不新增支援或略過。final 匯出禁用規則不變，不測下載落盤。
6. 單擊、拖移與鍵盤不互相誤觸；選表與搜尋欄位入口一致；明細未選取提示及禁用原因可發現。代表窄畫面仍能完成順序閱讀及來源返回。
