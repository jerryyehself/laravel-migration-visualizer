## 要解決的問題
現有表搜尋、聚焦與明細已交付；需要證明欄位查找或關係導覽的具體缺口。

## 候選方案與取捨
A：改善既有表導覽並按證據補欄位搜尋。B：新增多種圖形布局。C：加入 models 關係。A 範圍小；B 未必解決查找；C 增加證據模型。

## 選定方向（待核准）
採 A，但實作前補明確互動規格並核准，不重做既有功能。

## 範圍與可派小任務
1. 盤點現有搜尋／明細並重現 R1 阻礙。
2. 定義欄位搜尋結果、快照範圍、無匹配與未知狀態。
3. 若直接 FK 鄰居導覽有需求，定義不隱藏／不更改 schema 的 view 行為。
4. UI adapter 只讀當前快照；React state 只保存選取與視窗。

## 排除項目
Eloquent 解析、猜多型 FK、大圖性能保證、新布局算法、寫回 PHP。
既有 core 不做 IO／不執行 PHP／不連 DB、結構 diff 不猜 rename、lastValidSchema 不補 finalSchema 的契約延續。

## 驗收條件
能找到指定欄位及所屬表，辨識直接 FK；切換快照不沿用不存在物件；搜尋與導覽不更改分析／匯出 DTO；完成相關互動驗收。
