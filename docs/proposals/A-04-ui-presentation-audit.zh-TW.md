## 修訂 2：操作流程與表的線性變化

| 觸發 | 目前實際行為／來源 | 操作問題 |
|---|---|---|
| 在下方分析順序選 migration | `ProjectResults.tsx:124` 只呼叫 `onSelect(index)`；上方 `snapshotId` 是另一份 state | 逐檔摘要已換檔，ERD 仍可能停在 final 或別份快照；畫面沒有統一的目前步驟 |
| 在上方 ERD 選單切換 migration 快照 | `ProjectResults.tsx:99` 更新 snapshotId／清 focusTarget，不同步下方 selected migration | 圖與摘要可指向不同 migration，兩種選擇要自行維持一致 |
| 點圖上的資料表 | `SchemaGraph.tsx:49`、`:111` 啟動拖移；沒有呼叫 focusTable 或更新 focused | 視覺上像可選表，實際要用另外的「聚焦資料表」按鈕才能取得表明細；鍵盤方向鍵也只移動表 |
| 從聚焦清單選表／搜尋欄位 | `TableDetails.tsx:22` 表明細收合區依 activeColumn／openOnSelection 自動展開；一般聚焦表仍需再展開 | 類似選取動作有不同展開條件；來源按鈕又置於該明細內，入口可見性依賴先前動作 |
| 切到下一份快照 | `SchemaSnapshots.tsx` 使用 active.id 作 graph key；graph 本身保存查詢／表選取／視野 | 圖重新建立，需重新搜尋與聚焦；不適合連續追同一張表 |
| 要選第 N 份的前／後／比較 | `schema-snapshots.ts` 為每檔產生三個選項，另有 initial／final，總共 3N+2 | 100 檔就有 302 個選項；這是選項數，不是效能量測。沒有前一份／下一份入口 |

現行可行的手動路徑：選已知快照 → 搜尋／聚焦表 → 展開表明細，讀按順序列出的名稱直接涉及操作 → 再到 ERD 選單選對應 migration 的套用前／後或比較 → 重新聚焦該表。也可從逐檔摘要的 Before／After 物件按鈕跳圖，但下次換檔仍須再操作。已刪除的表要回到它仍存在的較早快照尋找。

R4 的直接涉及操作清單是既有能力；不是每次變更後的表狀態，也不是跨 rename 的物件歷史。R5 是單份 migration 閱讀；兩者不能宣稱已交付「選一張表後連續看演變」的完整主流程。

## 候選方案與取捨

| 方案 | 優點 | 成本／風險 |
|---|---|---|
| 只改文字、範例入口與進階資訊分層 | 範圍小，沿用 DTO 與已有功能，易審查 | 長頁面與來源往返仍可能繁瑣 |
| 上述整理加分析後收合輸入／完整表格 | 可讓分析結果更突出，減少重複展開 | 要驗證定位編輯會展開輸入、鍵盤焦點及結果失效行為 |
| 統一逐份閱讀的選取與入口，再整理顯示 | 直接處理本次回饋：選檔、圖、摘要同步，沿順序追表更容易 | 超過純文案整理；須定義圖表單擊／拖移區別、來源預覽返回、快照未知與表不存在的狀態 |
| 重做成固定工作區／側欄／分頁布局 | 有機會整合圖、檔案與明細 | 選取、焦點、捲動與比較布局影響較大；需具體畫面方案及新增驗收，先不綁進第一批 |

## 建議方向、範圍與排除

修訂 1 建議的收合／文字整理不足以處理新回饋。修訂 2 建議優先討論「統一逐份閱讀的選取與入口」，顯示整理列為配套；尚未核准。具體候選為：

1. 清楚區分「專案結構總覽」與「逐份 migration」檢視。總覽的 final 未知保持未知；逐份檢視只有一個目前 migration，圖、摘要與診斷都依它呈現。
2. 選一份 migration，再用「套用前／套用後／前後比較」選側別；提供前一份／下一份，依原始分析順序移動，不需要在 3N+2 選單內反覆找檔。
3. 單擊圖上的表可選取並查看明細；拖移繼續調整位置。鍵盤也須能選取，不能只有移動功能。明細區有固定入口與清楚的未選取提示，不依不明顯的先前操作突然出現。
4. 明確選中的表名稱，在逐份切換時保持為查看目標；該側沒有表就顯示「此時點不存在」，快照未知就顯示「未知」，不複製另一側資料。前後比較兩側各讀自己的快照。
5. 表明細內沿用 R4 名稱直接涉及的操作清單，點一項可切到對應步驟；失敗／阻擋操作保持未套用標示，不叫成已發生的結構變更。來源預覽保留返回原結構的上下文。

這是候選操作流程，不是已交付能力；不追蹤跨 rename 身分。若要求自動追蹤表改名、專屬表歷史 DTO、跨步驟比較或時間軸，要另立範圍，不能混入 UI 整理。

像後端 service 已回傳每份 migration 的 before／after／diff DTO，畫面需用同一個步驟選取讀它們；不應讓圖與摘要各自選不同 DTO。這不是新增 Laravel app service 或解析 model。新增顯示標籤不得把缺省值補成資料庫預設，不得把 false、0、null 轉成同一種空值。

本批不新增核心相容性、略過失敗、未知 final 的推測、migration 生成、動畫、持久化、Git／DB 分支、CI 整合或背景排程。不刪既有來源定位／副本修正／還原／搜尋／比較／匯出能力。JSON 匯出契約與暫緩下載互動／落盤驗收維持。

| 待核准第一批（開發端） | 使用者確認具體方案、範圍與修訂 | 修訂 2 的統一步驟／側別選取、表明細入口及順序導航；顯示整理範圍另確認 | 選檔後圖／摘要／診斷一致；前後切換保持表名稱目標；單擊／拖移／鍵盤互不衝突；不存在與未知不同；PHP 來源返回保留上下文；修改輸入使舊結果失效；必要 web tests／typecheck／build 與瀏覽器驗收由開發端執行 | 不延伸核心契約、跨 rename 追蹤、全新時間軸或部署；不重啟已暫緩的下載驗收 |

失敗原因及未知狀態不能藏在技術 JSON 裡；已知空 schema 與未知 schema 必須維持不同呈現。診斷可有摘要，但使用者仍須能讀到原因及定位來源。rename 的明確操作與結構 diff 的移除／新增仍分開。
